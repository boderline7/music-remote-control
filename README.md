# 车机桥接（18766）

给「车机助手」加一个 HTTP 口，让手机网页能读到车机卡片、能点卡片上的东西。

**原则：车机助手的代码一个字节都不改。** 全部通过反射 + ContentProvider 启动钩子挂上去。

原有两个工程（`车机助手_改版工程`、`车机遥控_工程`）全程只读，只引用了它们的 apktool / keystore / 解包目录副本。

---

## 端口三条线

| 端口 | 谁提供 | 什么时候在 |
|---|---|---|
| **18766** | 车机助手（本工程的 dex） | **常驻**。三重触发：ContentProvider（进程一起来）+ 前台服务 START_STICKY（进程被回收）+ 开机广播；跟音乐模式无关 |
| **18764** | 桥接包（官方网易云模式） | 官方音源在跑时提供遥控页 + WebSocket |
| **18765** | 网易云音乐车机版（`work/cloudmusic-car/app`，包名 `com.cloudmusic.car`） | 这个 App 在跑就由它提供；页面源码在 `web/remote.html` |

18764 和 18765 是同一个东西的两条来源，**同一时刻只有一个在跑**（音源只有一个）：
官方网易云就绑 18764，第三方自研就由它占 18765，桥接包不抢。

**18765 那页也是我们的**：它不是外部 App 的黑盒，`work/cloudmusic-car/app` 就是它的工程，
页面在 `web/remote.html`，构建时由 `build_remote.sh` 复制进 `app/src/main/assets/remote.html`。
改这里、重出 `网易云音乐车机版` 这个包，车上的 18765 才会变。

车控只走 18766，所以「没放歌」「第三方在放」都不影响车控。

**手机 App 里不用管端口**：只有一个 WebView，先探 18766（车机助手常驻），
进去后由页面自己的「车机控制 / 音乐控制」切换条再探音乐源；18766 不通才退 18765 / 18764。
进 App 默认落在音乐控制。

**浏览器里只用 18766 这一个地址**：18766 车控页顶部就是统一的切换条，
点音乐就把对应页面用 iframe 贴进同屏 —— 页面再怎么跳、怎么刷，都只在框里，切换条永远点得到。
框里要是空白，点右边 `↗` 单独打开。三个端口下发同一份外壳，切换条长得一样。

**三个页面用同一套参数收掉重复的壳**：

| 参数 | 谁带 | 页面做什么 |
|---|---|---|
| `embed=1` | 切换页签把对端 iframe 进来时 | 收掉自己的顶栏，只留内容，避免两层头 |
| `client=android` / `client=ios` | 手机 App 打开页面时 | 只是客户端来源标识，随握手上报；切换条仍由页面自己画 |
| `cv=` | 手机 App | 版本号，随握手上报给车机侧 |

这套参数三页都认（18766 车控、18764 桥接、18765 网易云车机版）。

18766 起来后，通知栏会有一条常驻通知「车控桥接 · 18766 常驻中」（最低优先级、无声）。它的作用是让系统不再回收这个进程——有它才叫真的常驻。

**新装的车机助手要先手动打开一次。** 安卓对「刚安装还没启动过」的应用处于 stopped 状态，开机广播不会投递，所以第一次装完必须点一下桌面助手图标（或重启车机），之后才由服务自己维持。

## 手机端（安卓 / iOS）

手机这一侧只有一个 App、一个 WebView：选/填车机 IP，连上后由**页面自己的顶部切换条**
在「车机控制」和「音乐控制」之间切。不翻译协议、不重画界面 —— 车控页和音乐页有什么，
手机上就有什么。**进 App 默认落在音乐控制。**

**不需要理解端口**。App 先探 18766（车机助手常驻，页面里再去探音乐源）；
18766 不通才退 18765 / 18764。切到音乐后由页面按当前音源决定连哪一个：

| 端口 | 谁提供的 |
|---|---|
| 18766 | 车机助手（常驻），车控页 |
| 18764 | 桥接包（官方网易云模式） |
| 18765 | 第三方网易云车机版自己发的页面 |

18764 / 18765 同一时刻只有一个在跑，页面自动进在跑的那个。**切换条在页面里，
App 不再画一层** —— 3.1 那代是原生双 tab + 两个 WebView，结果「两层切换、两条状态栏」，3.2 已改掉。

哪个通，哪一侧就亮；不通的点进去是一句「到车机上打开一次 XX」+ 点一下重试，不会白屏。

**浏览器 / 车机屏幕**和手机看到的是同一份外壳：顶部「车机控制 / 音乐控制」切换条，
点「音乐控制」用 iframe 把音乐页贴进同屏，右侧 `↗` 可以单独打开。
`client=android` / `client=ios` 只是让车机侧知道谁连进来了，不影响切换条的显示。

**返回键**：回到连接页。

地址列表：

- 手动加的地址存本地（最多 12 条），下次打开直接点。安卓长按删除，iOS 左滑删除
- 扫出来的结果不保存，换网络重新扫一次

| 平台 | 拿什么 | 怎么出 |
|---|---|---|
| 安卓 | `dist/车机遥控_手机端_v3.2.1.apk` | `bash build_phone.sh` |
| iOS | `dist/车机遥控_手机端_iOS_v2.1.1.ipa` | `bash build_ios.sh`（推 `phone-ios` 分支，自动出包） |

iOS 在这台 Windows 上编不了（Xcode 只跑在 macOS）。两条路：

1. Mac 上 `cd work/phone/ios && xcodegen generate`，用 Xcode 打开 `CarRemote.xcodeproj` 直接装；
2. `bash build_ios.sh` 把 `work/phone/ios` 单独推到 `boderline7/music-remote-control` 的 `phone-ios` 分支，
   `ios-phone.yml` 在 macOS runner 上出**未签名 IPA**，在 Actions 里下载 `CarRemote-unsigned-ipa`，
   再用 Sideloadly / AltStore 用本机 Apple ID 签名装进去。主分支不受影响。

细节见 `work/phone/ios/README.md`。

## 界面怎么用

**车机里打开「汽水音乐」入口页**（`com.luna.music.car` 的 Main）：

- 按钮两行五个：**启动桥接 / 启动音乐**；**重启 / 停止退出 / 刷新**。按下会变亮，点了有反馈
- **启动桥接**：拉起 18764 桥接服务（当前是第三方音源时会提示先切回官方）
- **启动音乐**：把播放器叫到前台，再补一个播放键——上次是暂停状态也能开播
- **重启**：音乐先停再起，同时请求 18766 软重启；18766 完全不通时会拉起车机助手。两个一起重启
- **停止退出**：停音乐桥接、关 18764，再把 App 移出任务栈——车机上没有可靠的后台清理，退出得自己收尾
- 两行地址栏：蓝色 18764（音乐）、绿色 18766（车控），**只显示不可点**
- 状态框顶部先写清两条线：`车控 18766：在线` / `音乐 18764：运行中`，下面一行 `探测：` 写明每个地址试出来什么
- 车控探测在后台线程跑，不占主线程；连不上时界面照样能点
- 小状态栏常驻显示 `音乐：xx　车控：在线/离线`
- App 里不再有诊断按钮：车机屏幕没法选中复制，诊断统一放到车控页的设置里（见下）

**手机网页**（`http://<车机IP>:18766/` 或音乐端口）：

- 顶部固定一条 **车机控制 / 音乐控制** 切换，点哪个就把哪个页面用 iframe 贴进当前页，
  **不跳转、不改地址栏**，所以不会出现「闪一下又回原页」；三个端口下发的是同一份外壳
- 被嵌进去的那一侧带 `?embed=1`，会把自己的切换栏和顶栏收起来，不套娃
- 这条切换浮在断线遮罩之上：音乐连不上时照样能切到车控，反过来也一样
- 「音乐控制」上的小圆点是音乐端口探活：绿=在跑，红=没起来，红了点它会提示先开车上的音乐 App
- 页面里的端口地址由服务端按请求 `Host` 填好（`{{HOST}}`），客户端脚本挂了也点得动
- 车机设置面板里加了「车控 18766 · 常驻」和「打开车控页」按钮
- 车控页：上半部分是车机助手的卡片（配色/圆角/字号都来自 `/cards` 的 `style`），下半部分是动作表（两组：空调 / 底盘），点一下让助手自己执行
- 空调那组下面还有两行**风量**（前排 1-7、后排 0-4，0 是关），减/加各一键。
  车机助手自己的界面是滑条，方法名筛不出来，所以单独走 `/fan`，命令号和档位范围照抄原界面
- 卡片下面一行**温度**：`−  数字  ＋`，数字居中、两侧加减，15-30 ℃ 整度，走 `/temp`（**没有滑条**）
- 再下面是**座椅**：只有「关 / 3 档」两态。前排加热、通风各两个座，后排只有加热两个座，
  **后排通风已删除**（这台车既没有命令号也没有状态位）；点一下按原厂 `sendSeatCommand`
  的语义下发（data = 目标档位 + 1），走 `/seat`，回读只用于点亮和提示
- 车控页右上角 **齿轮** → 「设置」：顶部是连接状态和「最近一次操作」，下面四个分段
  **诊断 / 操作记录 / 车况 / 动作表**，每段都是同一套 **生成 → 复制 → 下载**，切过去自动取一次
- **操作记录**：每次点按钮的结果和耗时——谁成功了、谁报了什么错、花了多少毫秒，最新的在最上面。
  「点了没反应」先看这一段
- **车况**：每张卡、每一项的名字和值，某张卡缺什么发这段比截图清楚；**动作表**：当前能执行的项和方法名，
  方法不存在会标「已隐藏」
- 底部 **全部导出** 把四段合成一个 txt 一次拿走；**清空记录** 只清操作记录，不动服务
- 点完按钮，卡片里变化的数值会**绿一下**（4 秒内有效），一眼看出哪项真的动了
- 手机浏览器里复制/下载都可用；App 内或微信里下载不弹窗就长按文本全选

车控页和音乐页是两条独立通道：音乐 WebSocket 断了，车控照样能用，反之亦然。

## 构建

```bash
bash compile.sh       # 改完 Java 跑这个
python build.py       # 出车机助手包
bash build_remote.sh  # 出网易云车机版 + 汽水桥接包
bash build_phone.sh   # 出安卓手机端
```

`build.py` 构建时会把 `work/apk_decoded` 复制到 `D:\cbwork\bridge_build`（ASCII 路径，否则 apktool 编 res 会挂），
在那个副本里加 provider 声明、改版本号，然后打包。

`build_remote.sh` 先把网页同步进 `work/cloudmusic-car`，再
`gradlew :lunastub:assembleRelease --offline`。Gradle 与 JDK 17 都走本机缓存，不需要联网。

`build.py` 还会把 `web/car.html` 拷成 APK 里的 `assets/carbridge.html`——18766 首页就是它，改页面不用重新编 Java。

**各端的包名、版本号、签名：**

| | 包名 | 版本 | 签名 |
|---|---|---|---|
| 车机助手 | `com.navi.tool` | 25 / 18.73-mod | `debug.keystore` |
| 桥接包 | `com.luna.music.car` | 61 / 2.10.18 | `keystore/carremote.jks` |
| 手机端（安卓） | `com.carremote.client` | 28 / 3.2.1 | `keystore/carremote.jks` |
| 网易云车机版 | `com.cloudmusic.car` | 54 / 2.5.2 | `keystore/carremote.jks` |

每次改动递增版本号、各自出包；没变的端沿用上一版，不重复构建。版本号一动就是新 App，覆盖安装会断，车机上的桌面图标和授权都得重来。

## 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/` | 车控页（`assets/carbridge.html`，手机/车机浏览器直接打开） |
| GET | `/ping` | 存活 + 绑定状态 |
| GET | `/acts` | 动作表（分组）。只列车机助手里**真实存在**的方法，不存在的不返回 |
| GET | `/cards` | 卡片数据 + 样式参数 |
| POST | `/act` | `{"a":"handleHvacAutoClick"}`，带开关值的再补 `"v":1` |
| POST | `/fan` | 前后排风量：`{"v":3}` 改前排（1-7），`{"r":0}` 改后排（0-4，0 关）。不带参数就是读当前档位 |
| POST | `/temp` | 温度：`{"v":26}`，15-30 ℃ 整度。不带参数就是读当前温度 |
| POST | `/seat` | 座椅：`{"p":"rl","k":"heat","lv":3}`，`p` 取 `fl/fr/rl/rr`，`k` 取 `heat/vent`，`lv` 是目标档位（0 关 / 1-3）；不带参数读四座状态 |
| GET | `/probe` | 诊断用：能力/字段/方法清单（页面不再用它渲染） |
| GET | `/diag` | 诊断文本（纯文本）。端口、引擎绑定、包版本、动作项数、日志全在里面 |
| GET | `/diag.txt` | 同上，带 `Content-Disposition`，点链接直接存成文件 |
| GET | `/acts.log` | 操作记录文本：每次 `/act` 的结果、耗时、错误，最新的在上面 |
| GET | `/acts.log.txt` | 同上，带下载头，存成 `act-log.txt` |
| GET | `/cards.txt` | 车况快照文本：每张卡每项的名字和值 |
| GET | `/acts.txt` | 动作表清单：按钮文字、方法名、参数，方法缺失的会标出来 |
| GET | `/dump` | 全量打包：诊断 + 车况 + 动作表 + 操作记录（`/dump.txt` 带下载头） |
| GET | `/log/clear` | 清空操作记录（只清计数与缓冲，不动服务） |
| GET | `/restart` | 软重启：重抓 Activity / Helper，再要一次前台服务；返回是否绑上 |

> `/act` 的参数是**方法名本身**（`handleTrunkClick` / `actionSetDriveModeSport`），
> 不再经过「id → 驼峰 → 猜方法名」那一层，名字对不上就是没有，不会点了没反应。
> 老写法（`steering_heat` 这类 id）仍会退回旧的匹配逻辑，不会断链。

## 自检页怎么覆盖

内置页在 dex 里，改起来要重新打包。想改前端又不想打包：

```bash
adb push my.html /sdcard/Android/data/com.navi.tool/files/web/index.html
```

服务端每次请求会优先读这个文件。

## 已知边界

- **依赖桌面助手在跑。** Helper 实例是桌面助手 Activity 里的那个，Activity 不出现就拿不到。
  车机助手是常驻桌面组件，正常情况下没问题；`/diag` 里的「界面 / 引擎」两行会明确告诉你有没有绑上。
- **只读引用，不新建 Helper。** 构造第二个 Helper 会扰乱界面结构，绝对不做。
- **弹窗类操作**（吹风模式、座椅按摩、香氛）走的是独立窗口，数据能读，点击要看 `handle*` 方法是否覆盖。
- **手机上验证不了车机数据。** 测试机没有车机总线，`getCarInfoValue` 会返回空，这是正常的。
