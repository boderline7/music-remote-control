# 网页

## 外壳

`web/shell/` 四件，由 `web/stitch.py` 拼进三个页面：

| 文件 | 内容 |
|---|---|
| `_shell.css` | 样式变量与三个 tab 的布局 |
| `_shell.body.html` | 状态行 + 切换条 + 设置面板 |
| `_shell.js` | 外壳逻辑：选 tab、贴 iframe、画状态点、设置面板 |
| `_shell.boot.js` | 启动前的最小脚本（避免闪白） |

页面里保留三个标记，重复运行幂等：

```
<!--@shell:head-->   ... <!--@/shell:head-->    <style> + 启动脚本
<!--@shell:body-->   ... <!--@/shell:body-->    状态行 / 切换 / 设置面板
<!--@shell:script--> ... <!--@/shell:script-->  外壳逻辑
```

`web/pages/dvr.html` 没有这三个标记，不参与拼接 —— 它是独立页。

```bash
python web/stitch.py           # 拼进三个页面
python web/stitch.py --check   # 只检查标记在不在
```

**改过 `web/shell/*` 必须重跑一次**，否则打进包里的还是旧外壳。

## 三个 tab

顶部固定一条 **车机控制 / 音乐控制 / 行车记录仪** 切换，点哪个就把对应页面用 iframe 贴进当前页，
**不跳转、不改地址栏**，所以不会「闪一下又回原页」。

- 被嵌进去的那一侧带 `?pane=xxx`，会把自己的顶栏收起来，不套娃
- 切换条浮在断线遮罩之上：音乐连不上时照样能切到车控，反过来也一样
- 「音乐控制」上的小圆点是音乐后端探活：绿 = 在跑，红 = 没起来，红了点它会提示先开车上的音乐 App
- 记录仪状态点由记录仪页自己 `postMessage` 上报，外壳全程不猜、不主动探 18767
- 从 18766 进来时音乐页直连在跑的那个后端端口（18765 / 18764），不走 `/music` 反代 —— 音乐控制靠 WebSocket，直连是唯一验证过没问题的那条路

## 去缓存

外壳拼接时按内容算一个构建号，iframe 地址带上 `&b=xxxx`。内容一变号就变，
装新包后不会复用旧文档，不用再手动清缓存；同一个包重复打开仍走缓存，不会变慢。

## 设置面板（车控页右上角齿轮）

顶部是连接状态和「最近一次操作」，下面四个分段，每段都是 **生成 → 复制 → 下载**，切过去自动取一次：

| 分段 | 内容 |
|---|---|
| 诊断 | 端口、引擎绑定、包版本、动作项数、进程日志 |
| 操作记录 | 每次点按钮的结果和耗时，最新的在最上面。「点了没反应」先看这段 |
| 车况 | 每张卡、每一项的名字和值，比截图清楚 |
| 动作表 | 当前能执行的项和方法名，方法不存在会标「已隐藏」 |

- **全部导出**：四段合成一个 txt 一次拿走；**清空记录**只清操作记录
- **停止记录 / 开始记录**：停掉后 18766 不再往缓冲写新行，已有的留着（提示会告诉还剩多少行），
  正好把出问题那一段钉住，不被后续正常日志冲掉
- 导出是 UTF-8 纯文本：安卓手机端走原生存盘写进系统「下载」目录（形如 `车机诊断_20261117-1929.txt`），
  浏览器直接跳服务器的 `.txt` 地址；复制按钮在没有内容时会先自动取一次，不再「点了没反应」
- 页面是 `http://` 明文，`navigator.clipboard` 在非安全上下文里不存在，所以复制走 `execCommand` + 可长按全选的兜底

## 车控页

上半部分是车机助手的卡片（配色/圆角/字号都来自 `/cards` 的 `style`），下半部分是动作表（空调 / 底盘两组）。
点一下让助手自己执行，卡片里变化的数值会**绿一下**（4 秒内有效），一眼看出哪项真的动了。

- **风量**：前排 1-7、后排 0-4（0 是关），减/加各一键。车机助手自己的界面是滑条，方法名筛不出来，
  所以单独走 `/fan`，命令号和档位范围照抄原界面
- **温度**：`−  数字  ＋`，15-30 ℃ 整度，走 `/temp`，没有滑条
- **座椅**：只有「关 / 3 档」两态。前排加热、通风各两个座，后排只有加热两个座
  （后排通风已删除 —— 这台车既没有命令号也没有状态位）；走 `/seat`，`data = 目标档位 + 1`
- **悬架联动**：只保留「开」，「关」已从动作表移除

## 车机上的入口页（桥接包 Main）

两行五个按钮：**启动桥接 / 启动音乐**；**重启 / 停止退出 / 刷新**。按下会变亮，点了有反馈。

- **启动桥接**：拉起 18764（当前是第三方音源时会提示先切回官方）
- **启动音乐**：把播放器叫到前台，再补一个播放键 —— 上次是暂停状态也能开播
- **重启**：音乐先停再起，同时请求 18766 软重启；18766 完全不通时会拉起车机助手
- **停止退出**：停音乐桥接、关 18764，再把 App 移出任务栈
- 两行地址栏：蓝色 18764（音乐）、绿色 18766（车控），只显示不可点
- 状态框先写两条线：`车控 18766：在线` / `音乐 18764：运行中`，下面一行 `探测：` 写明每个地址试出来什么
- App 里不再有诊断按钮：车机屏幕没法选中复制，诊断统一放到车控页的设置里

## 记录仪页

**普通 / 事件两组，各自标出当前目录 + 最新 5 条**，点一行直接下载（不预览、不内嵌播放器），
顶栏「连接 / 断开 / 指定 IP」。

**纯手动**：打开页面不自动连接，只有点「连接」才探 IP 并读一次目录；点「断开」之后页面不轮询、不预热，
外壳也不探 18767，18767 上不会再收到任何请求。记住的 IP 保留，再点「连接」一探就到。

列表默认只显示最新 5 个，其余点「更多（共 N 条）」展开 —— 记录仪一页几十上百条，一次全渲染很慢。
解析不出列表时，页面直接把 `/dvr/fs?p=<目录>` 用 iframe 显示（记录仪自己的目录页原样转出来，链接已改写）。
