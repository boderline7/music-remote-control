# 架构

## 一句话

车机助手（`com.navi.tool`）本身没有 HTTP 口。本工程把一段自己的 dex 注入进它的 APK，
在它进程里挂一个 `ServerSocket`（18766），把它的卡片数据和按钮方法暴露成 HTTP；
再让同一段代码兼做网关，把音乐和记录仪的请求转给另外两个 App。

**车机助手的代码一个字节都不改。**

## 注入方式

三层，越靠前越优先被系统调用：

| 层 | 组件 | 作用 |
|---|---|---|
| ContentProvider | `BridgeProvider` | 进程一起来系统就调用 `onCreate`，最先挂上 |
| 前台服务 | `BridgeService` | `START_STICKY`，进程被回收自己回来；常驻通知让系统不轻易动它 |
| 开机广播 | `BridgeBoot` | `BOOT_COMPLETED` / `QUICKBOOT_POWERON`，车机一启动就顶服务 |

`Bridge.install()` 拿到桌面助手 `DesktopAssistantActivity` 里的 `carControlHelper` 反射实例，
所有车控动作都是调它自己的方法 —— 不新建 Helper（会扰乱界面结构，绝对不做）。

## 四条端口线

| 端口 | 谁提供 | 生命周期 |
|---|---|---|
| **18766** | 车机助手（本工程的 dex） | 常驻，跟音乐模式无关 |
| **18767** | 桥接包 `DvrSvc` | 常驻，跟音源无关 |
| **18764** | 桥接包（官方云音乐模式） | 官方音源在跑时 |
| **18765** | 云音乐车机版 `com.cloudmusic.car` | 这个 App 在跑时 |

18764 和 18765 是同一个东西的两条来源，同一时刻只有一个在跑：官方云音乐就绑 18764，
第三方自研就由它占 18765，桥接包不抢。

**18766 为什么不能由桥接包提供**：`carControlHelper` 是桌面助手 Activity 里的对象，
跨进程拿不到。桥接包再装一份 `Bridge` 也抓不到那个实例，只会在自己的进程里空转。
所以 18766 必须在车机助手进程里，这也是「注入 dex」这套做法存在的原因。

## 统一入口网关

18766 起的 HTTP 服务里有一个 `Gateway`（`src/bridge/src/.../Gateway.java`），
纯 JDK `ServerSocket` 做的 TCP 反代，**只透传字节，不解析协议**。

路由规则：

| 条件 | 去向 |
|---|---|
| 带 `Upgrade: websocket` | 音乐后端（车控是纯 HTTP，不用 WS） |
| `/music/*` | 音乐后端，转发前去掉 `/music` 前缀 |
| `/api/*` | 音乐后端，路径原样（日志、音源切换、重启服务都在这下面） |
| `/dvr` 或 `/dvr/*` | 18767，路径原样 |
| 其余 | 留在本地，走车控路由 |

音乐后端用 TCP 探活选定，缓存 3 秒、优先 18765，命中后做一次轻量复查。
`/gateway` 把选定结果和端口返回给外壳画状态点。

## 外壳

三个入口下发的是**同一份外壳**（`web/shell/` 四件由 `web/stitch.py` 拼进页面）：
从 18766、18765、18764 哪个进去，看到的都是同样的三个 tab、同一套状态点与失败提示，
记录仪一律指向 18767。记录仪页 `web/pages/dvr.html` 不参与拼接，它是独立页。

## 手机端

手机侧只有一个 App、一个 WebView：选/填车机 IP，连上后由**页面自己的切换条**在三个 tab 之间切。
不翻译协议、不重画界面 —— 页面上有什么，手机上就有什么。

- 安卓按 18766 → 18765 → 18764 顺序并行探测，18766 优先
- iOS 只探 18766 / 18765（两个端口，命中即停）

所以「只有桥接包在跑」时 iOS 连不上，这是已知差异。

## 常驻与首次安装

18766 起来后通知栏会有一条常驻通知「车控桥接 · 18766 常驻中」（最低优先级、无声）——
它的作用是让系统不再回收这个进程，有它才叫真的常驻。

**新装的车机助手要先手动打开一次。** 安卓对「刚安装还没启动过」的应用处于 stopped 状态，
开机广播不会投递，所以第一次装完必须点一下桌面助手图标（或重启车机），之后才由服务自己维持。

## 已知边界

- **依赖桌面助手在跑**：Activity 不出现就拿不到 Helper。`/diag` 里的「界面 / 引擎」两行会写明有没有绑上。
- **只读引用，不新建 Helper**：构造第二个 Helper 会扰乱界面结构。
- **弹窗类操作**（吹风模式、座椅按摩、香氛）走独立窗口，数据能读，点击要看对应的 `handle*` 方法是否覆盖。
- **手机上验证不了车机数据**：测试机没有车机总线，`getCarInfoValue` 返回空是正常的。
