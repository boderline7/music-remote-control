# 云音乐定制 · 需求

## 背景

原作者停更，我们接手维护。直接在源码上备份后动手，不走脚本那套。

## 一、歌词跳转（核心需求）

**现状**：车机助手里，单击悬浮音乐卡片会打开它自己内置的全屏歌词页（`LyricsFxView`），不是我们要的。

**目标**：点击悬浮卡片音乐时，悬浮卡片上的歌词/入口**直接跳转到云音乐原有的歌词大屏界面**（下滑收起那个，`NowPlayingScreen`），不经过车机助手的内置歌词页，也不经过桥接包。做成 active 状态后点击就直接跳过去。

**做法方向**：
- 云音乐的歌词大屏是 Compose 内部页面（`nav.nowPlayingOpen` 控制），不是独立 Activity，现在没有外部入口能直接打开。
- 把它做成可被外部激活的 active 状态：`MainActivity` 已是 `exported=true` + `singleTask`，加一个自定义 action（`com.cloudmusic.car.OPEN_LYRICS`），在 `onCreate` / `onNewIntent` 里读到就把 `nowPlayingOpen` 置为 true，直接进歌词大屏。
- 车机助手侧：把卡片点击回调（歌名 `textSongTitle` → `n0.onClick` → `lambda$initViews$57` → `openLyricsFxPage`）改成发这个 Intent 拉起 `com.cloudmusic.car`。
- 悬浮歌词自身的双击关闭、单击打开保持不变，不在本次范围。

## 二、音源槽位

- 用**酷我的槽位（source=1/4）**改成云音乐 `com.cloudmusic.car`，不动汽水（source=5）。酷我私有 SDK（`cn.kuwo.autosdk`）不再用。
- 取消 source=6 通用音源的联网兜底搜词（拿歌名去 `search.kuwo.cn` 搜，会串台、费流量）。

## 三、两个 App 深度贴合（歌词滚动）

- 云音乐这侧已有逐字歌词（`WordLyricsParser` / KRC，走 MediaSession 的 `METADATA_KEY_KRC_LYRIC`）。
- 车机助手的 `LyricsAdapter.updateLyricsProgress` 目前只按行滚动，可考虑把逐字能力接过去。与第一节的跳转是两件事：跳转管"点进去"，逐字管"里面怎么滚"，这期是否接逐字待定。

## 四、桥接包改名 + 清理

- 名字改成「车控互联」这类，**去掉桥接相关功能**（原"烟雾"是打错字），不再带音乐桥接。
- 不再使用 `com.luna.music.car` 包名，也不再叫「汽水音乐」。
- 只保留文件传输（小绿传）和行车记录仪（18767 DvrSvc）；官方音乐桥接代码已在 `lunastub/src/parked`（不进 APK），可直接删除。

### 六、记录仪自动唤醒 + 两处修复（2026-11-25 追加）

- **18767 自动拉起**：`_shell.js` 的 `probeDvr()` 探测失败 → `GET 18766/dvrwake` → 车机助手 `DvrWake` 发显式广播 `com.yuhan.dvrcar.WAKE` → 车控互联 `WakeRcvr` 收到 `DvrSvc.start()` → 前端重探。网关 `Gateway.handle()` 转发 `/dvr/*` 失败时也会先唤醒再重试一次。全程后台，不启动任何界面。
- **二维码不恢复**：服务开关关闭时只清了 `ivQr`，没清 `lastQrUrl`/`lastQrBitmap`，`showQr()` 缓存判定「地址没变、图还在」直接返回 → 重新开启后二维码空白。已在关闭分支一并置空。
- **返回上级**：设置页按钮改为显式启动 `com.yuhan.xiaolvchuan.MainActivity`（`CLEAR_TOP|SINGLE_TOP`），回到二维码首页而不是退桌面；启动失败才 `finish()`。

### 七、记录仪并入车机助手（2026-11-25 追加）

用户判断独立维护一个「车控互联」包不划算，把行车记录仪代理（18767）整包搬进车机助手，小绿传文件传输不并（用原版 APK）。

- **搬了什么**：`lunastub` 的 `DvrProxy`/`DvrHttp`/`DvrServer`/`DvrCmd`/`Ip`/`Cfg`/`LogCapture`/`ServerIo` → `src/bridge/src/com/navitool/bridge/dvr/`，改包名，对外只留 public 的 `Dvr`。约 1300 行纯 Java，无 R 类依赖，直接 javac → d8 进 `classes3.dex`。
- **怎么起**：`BridgeService.onCreate` / `onStartCommand` 调 `Dvr.start(ctx)`（幂等）。18766 和 18767 同进程，进程在端口就在。
- **删掉的**：`DvrWake.java`（跨包广播唤醒）、`WakeRcvr`（对方侧接收器）、`Gateway` 的唤醒重试改成进程内幂等 start。`/dvrwake` 端点保留（前端在用），语义变成「确保在跑」。
- **页面**：`make.py` 的 `inject_page()` 额外拷 `web/pages/dvr.html` → `assets/dvr.html`，`DvrServer` 的 `GET /` 直接吐它。
- **编译修正**：`build_bridge_dex()` 的 `glob("*.java")` → `rglob`，否则 `dvr/` 子包不进 dex。
- **车控互联停用**：`dist/` 不再产 `车控互联_*.apk`，`install.sh` 改为先卸 `com.yuhan.dvrcar` 再装车机助手（两个包会抢 18767）。`lunastub` 模块代码保留但不再出包。

实测（M2011K2G / Android 12）：装车机助手后 18766、18767 同时监听；`18767/ping` → `{"ok":1,"port":18767}`；`18767/` 出记录仪页；`18766/dvr/state` 与 `18766/dvrwake`（`{"was":1,"fired":1,"now":1}`）均正常。
