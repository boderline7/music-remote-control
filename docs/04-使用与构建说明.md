# 04 · 使用与构建说明

## 一、装车机端

```bash
adb install -r "dist/cloudmusic-car-v2.2.2-遥控-debug.apk"
```

> **签名换了（1.2.0 起用自有签名库 `keystore/carremote.jks`）**：如果装过 1.1.x，直接覆盖会报
> `INSTALL_FAILED_UPDATE_INCOMPATIBLE`。先 `adb uninstall com.cloudmusic.car` 再装；卸载会清掉
> 登录状态，需要重新扫码。

包名 `com.cloudmusic.car`，应用名「云音乐 车机版」。**第一次装会覆盖原版**（applicationId 没变），
如果车机上是跑跑桌面里的功能包（`.ppmusic`），那是另一套东西，和本 APK 互不冲突、可共存。

装完打开 App：

1. 扫码登录网易云（用**网易云音乐 App** 扫，微信扫无效）。
2. 遥控服务**默认已开启**（进程启动时自动起，开机广播也会拉起），不用再手动点。
   想确认状态：左栏最下面「设置」→「手机遥控」。
3. 页面上会显示：

```
车机地址  192.168.x.x : 18765
手机浏览器遥控  http://carremote.local:18765
mDNS 就绪 · ap0 · 收 0 / 回 0
域名保活：已宣告 12 次 · 上次 43s 前
同时在线  0 / 4 台
```

**2.0 起没有 PIN、也不需要配对**：手机连上同一个 Wi-Fi，打开 App 或浏览器就能直接控制。
右栏「同时在线上限」默认 4 台，可用 +/− 调到 1~8；调小只影响之后的新连接，不会把正在用的手机踢下线。

同一栏下面的「歌单缓存上限」默认 12 份，可调 1~30：打开过的歌单会留在车机内存里，翻回来不用重新拉。
调小立即回收最久没用的那几份（点「清空」可全清），不影响正在播放的歌；下面那行 `已缓存 N 份 · 约 X MB` 是实际占用。

另外「设置 → 缓存」里多了一栏 **歌曲、歌词缓存上限**（默认 5 GB，可选 2 / 5 / 10 GB，音乐 : 歌词 = 9 : 1）：

```
歌曲、歌词缓存上限
实际场景：跑长途、进地库、过隧道没信号时，缓存的歌直接本地播放，不卡也不耗流量；
          歌词跟着歌一起留着，断网也能跟唱。默认 5 GB 大约装 1000 首无损（或 3000 首 320k）。
当前：音乐 5.0 GB · 歌词 512.0 MB（封面另算 256 MB）
        [ 2 GB ]   [ 5 GB ]   [ 10 GB ]
```

- **音乐那半改完下次启动生效**：音频缓存是 Media3 的 `SimpleCache`，上限在创建时固定，
  播放中重建会把正在放的歌打断，不值得为「立刻生效」冒这个险。
- **歌词那半立即生效**：超预算就按「最久没被读过」删（听过一次会把时间戳推后），留 10% 余量。
- 清空缓存按钮在它上面那一栏，点一次三个都清。

开关状态会持久化，车机重启后自动恢复；装了 `RECEIVE_BOOT_COMPLETED`，车机通电开机就会把服务拉起来
（部分 ROM 限制后台起前台服务时会降级为无通知运行）。

## 二、装手机端

```bash
adb install -r "dist/车机遥控-v1.8.7.apk"
```

> 手机端同名包也换了签名，1.1.0 及以前装过的要先 `adb uninstall com.carremote.client`。

打开后：

1. **自动发现**：手机和车机连同一个 Wi-Fi，稍等会出现「cloudmusic-car」，点「连接」。
2. **发现不到就手动连**：填车机 IP（就是车机页面上那个 `192.168.x.x`）和端口 `18765`，点「连接」。
3. 连上就直接进遥控界面，没有 PIN、没有配对。
4. 上次连的地址会记住，**以后打开就自动连**。

启动时如果上次的地址连不上，会在 2.5 秒后自动扫一遍当前 /24 网段找开着的 18765 端口。
手机端只保存上次的车机地址，卸载即清除。

## 三、日常使用

- 手机退出 App 或熄屏，车机音乐**照常播放**。
- 车机 IP 变了不用管：手机启动时会 ① 先连上次的地址 ② mDNS 发现 ③ 直接扫当前 /24 网段找开着的 18765 端口，三条路任意一条通就能连上，连上后记住新地址。
- 多台手机可以同时连（默认上限 4 台，车机页面可调 1~8）。任何一台的操作都会同步到所有手机的状态显示上。
- 想限制人数就把上限调小；想让某台手机掉线，直接在那台手机上点「断开」，车机不做拉黑。
- 手机端短暂断线时**不会**把遥控面板收走，只把左上角的点变成橙色并显示「重连中」，断开超过 3 次才退回连接页。
- 车机端挂了一个前台通知「手机遥控已开启」，作用是不让系统冻结进程。别手动杀掉它。
- 车机「设置 → 显示 → 全屏显示」：打开会隐藏状态栏和导航栏，配置持久化，重启仍是全屏；关掉就回到跟随系统的显示。
- 车机「资料库」页固定带一条自己的入口（我喜欢的音乐 / 最近播放 / 音乐云盘 / 设置），横屏竖屏都有，
  不用再点右上角头像绕一圈去设置。

## 三·五、手机端选歌（资料库）

遥控页不再有「歌单」按钮：音量条下面直接就是**车机账号**的资料库，跟着整页一路往下滚。

- 两张入口卡：我喜欢的音乐 / 音乐云盘；下面是「我创建的歌单」（不含收藏的别人的歌单）
- 点进任一列表 → 点某首歌 → 车机立刻从这首开始播；也可以点「播放」从头播
- 列表每页 40 首，翻到底点「加载更多」；左上角「‹ 资料库」退回到入口
- 资料库标题右侧的刷新图标可以重新拉一次列表

数据是**每次连上都现拉**：车机收到 `library` / `getTracks` 时才调网易云接口，所以网易云那边增删了歌单、收藏变了，
重新连一次或点刷新就是新的；已经打开的列表不会自己变。手机端不缓存、也不需要登录网易云。

## 四、电脑端联调（不装手机也能验）

```bash
# 只测握手 / 端口通不通
python _工具/wstest.py --host 192.168.1.23

# 2.0 起连上就是已认证，直接发指令 + 收 5 秒状态（不需要 pin / token）
python _工具/wstest.py --host 192.168.1.23 --cmd play --cmd getState --watch 5

# 跳转 / 调音量
python _工具/wstest.py --host 192.168.1.23 --cmd seek --seek 60000 --cmd setVolume --volume 20
```

正常输出长这样：

```
[state] 播放中 南方姑娘-赵雷 12000ms/320000ms 音量=15/30 seq=42
[ack] {"v":1,"type":"ack","id":"cmd-0","data":{"ok":true,"action":"play"}}
```

## 五、故障排查

| 现象 | 原因 / 处理 |
|---|---|
| 手机发现不到车机 | ① 两者不在同一网段（车机插 4G、手机连 Wi-Fi 最常见）；② 车机 Wi-Fi 开了 AP 隔离；③ 车机路由拦 mDNS。**先用「手动连接」直接填 IP 验证**，能连就说明只是发现失败，不影响使用 |
| 手动也连不上 | 车机页面上的 IP 可能取错了网卡（双网卡车机）。在车机 `adb shell ifconfig` 看 wlan0 的实际地址；端口被占时车机页面会显示「端口 18765 被占用」 |
| 提示「车机要求配对」 | 手机端 1.8 连到了 2.0 以前的旧车机端。升级车机端即可，2.0 起没有 PIN |
| 连上几秒就断、自动重连 | 车机上同时在线的手机超过上限。看车机「同时在线 N / M」，把 M 调大或断开一台 |
| 域名过一会打不开（IP 正常） | 看车机「域名保活」那行：`已宣告 N 次` 应该一直在涨、`上次` 在 45s 上下。停住了就重开一次遥控服务（详见 `docs/05`） |
| 遥控界面没有音量条 | 车机侧读不到 `AudioManager` 音量（车机把音量交给功放管了）。按设计不填假值，直接隐藏 |
| 进度条拖了没反应 | 车机对 `seek` 返回 `3003 NOT_AVAILABLE`（当前无可跳转媒体）。先放一首歌再拖 |
| 连上了但一直「未在播放」 | 车机没在放歌。手机端只会同步状态，不会凭空开始播放 |
| 熄屏几分钟后失联 | 已加前台服务（`RemoteService`，通知「手机遥控已开启」）。若仍失联，多半是系统级冻结（见下条） |
| **手机端一直「正在连接」，车机日志一条都没有** | 车机进程被系统冻住了（`/proc/<pid>/status` 显示 `State: T (stopped)`）。内核照常回 SYN，所以 TCP 能连上，但应用层不再读数据。处理：车机设置里把本应用加入「自启动 / 允许后台运行 / 不限制耗电」白名单。实测 vivo 手机即使挂前台服务仍会被 SIGSTOP，国产 ROM 需要手动放行；车机通常没有这类管控 |
| 音量拖动没反应 | ① 车机把音量交给功放管（读不到就隐藏音量条，见上一条）；② 应用退到后台时系统会忽略 `setStreamVolume`（Android Q 起的限制），车机端在前台时正常 |
| APK 装不上（INSTALL_FAILED_UPDATE_INCOMPATIBLE） | 签名不一致。1.2.0 起两端都用自己的 `keystore/carremote.jks`，装过旧包的必须先 `adb uninstall <包名>` |
| `INSTALL_FAILED_ABORTED: User rejected permissions` | 国产 ROM 的 USB 安装确认。有 root 时用 `adb push` 到 `/data/local/tmp` 再 `su -c 'pm install -r -t ...'` 可绕过 |

## 六、重新构建

```bash
export JAVA_HOME="<你的 JDK 目录>"        # 必须含 javac

cd 车机端/cloudmusic-car                   # 在工程根目录下
./gradlew assembleDebug        # 首次会下载依赖，约 5 分钟；之后增量 1 分钟内

cd 手机端/cloudmusic-remote                # 在工程根目录下
./gradlew assembleDebug
```

签名：两端根目录各有一份 `keystore.properties`，指向 `../../keystore/carremote.jks`（alias `carremote`）。
debug 与 release 都用它，所以 debug 包和 release 包可以互相覆盖安装。改密码就改这两份 properties 并重新生成 jks。

出 release 包（R8 混淆、体积小很多，但没在真机验证过，先别直接发）：

```bash
./gradlew assembleRelease      # 无正式签名库时自动回退 debug 签名
```

## 七、改了协议怎么办

1. 改 `proto/protocol.json`（唯一事实来源）。
2. `python proto/test_protocol.py` 必须 PASS。
3. 同步三处常量：`proto/Protocol.java`、车机端 `remote/RemoteConfig.kt`、手机端 `Protocol.kt`。
4. 版本号 `protocolVersion` +1，两端同时发。
