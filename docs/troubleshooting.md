# 排障

按「症状 → 先看什么 → 怎么办」查。凡是要看日志的，都从车控页右上角齿轮 → 设置 →「诊断」拿。

## 页面还是旧的 / 装完新包行为没变

**先看**：地址栏里的 `&b=` 有没有变。构建号由外壳内容算出，内容变了号一定变。

**怎么办**：

1. 改过 `web/shell/*` 却没跑 `python web/stitch.py` —— 页面里那段外壳还是旧的，重跑再出包
2. 出包了但没装 —— `dist/` 里的时间戳要晚于源码改动
3. 车机 WebView 缓存 —— 现在 URL 带构建号，正常不会再命中旧文档；真遇到就清一次 WebView 缓存

## 音乐无限读条，随后跳「与车机断开连接」

**先看**：遮罩上那行 `已停止（断开码 xxxx）`。断开码直接摆在界面上，不用翻日志。

| 断开码 | 含义 | 下一步 |
|---|---|---|
| `1006` | 握手被拒或连不上端口 | 直接从 `http://<IP>:18765/` 打开，看是不是页面本身的问题 |
| `1000` / `1001` | 服务端主动关 | 车机上音乐服务可能在重启 |
| 空 | 还没连上就断了 | 端口探活失败，先确认那个端口在跑 |

自动重连有上限：退避到 2 秒、连满 8 次（约 13 秒）还连不上就停，页面停在遮罩上，
不再拿 WS 握手当永不停止的流量打到车机上。恢复靠「立即重试」或从后台切回前台。

**已经排除的方向**：从 18766 进来时音乐页走 `/music` 反代曾经导致无限读条，
现在音乐页直连在跑的后端端口（18765 / 18764），地址栏仍是 18766。

## 日志看不了、复制不了、下载不了

三个不同原因：

1. **`/api/*` 没转发**：日志、音源切换、重启服务都在 `/api/*` 下。从 18766 进来时这些请求
   全被车机助手的本地路由 404 掉了。网关现在已经把 `/api/*` 原样转给音乐后端。
2. **复制按钮点了没反应**：按钮原先要求先点「生成」，没有缓存就只弹提示。现在没有内容会先自动拉一次。
3. **剪贴板不可用**：页面是 `http://` 明文，`navigator.clipboard` 在非安全上下文里不存在，
   只剩 `execCommand` 兜底，部分 WebView 会直接拦掉。兜底是把文本摊到可长按全选的框里。

**导出格式**：UTF-8 纯文本。安卓手机端走原生存盘写进系统「下载」目录；浏览器跳服务器的 `.txt` 地址，
带 `Content-Disposition`，存下来就是正经文本。App 内或微信里不弹窗就长按全选。

## 记录仪一直「已断开」

这是**设计如此**：打开页面不自动连接。

1. 点「连接」才会探 IP 并读一次目录
2. 点「断开」之后页面不轮询、不预热，外壳也不探 18767，18767 上不会再收到任何请求
3. 状态点由记录仪页自己上报，外壳不猜

**要确认 18767 在不在**：车机上打开 `http://<车机IP>:18767/ping`。不通说明桥接包没跑或 `DvrSvc` 没起来。

## 记录仪连上了但「普通录像」是空的

列表来自抓记录仪自己的目录页（`GET http://<记录仪IP>/SD0/NOR/M_video/`），扫全页 `href`。
空列表通常是这几种：

- 目录不对 —— 每组标题右边那行目录可以点，改成别的路径立刻重读，不用重新出包
- 记录仪换了固件，页面结构认不出 —— 页面会用 iframe 把 `/dvr/fs?p=<目录>` 原样显示，能点进去就说明网络通、只是解析没命中
- 网络不通 —— 记录仪必须与车机某网卡同段；不同段用「指定 IP」

页面上的状态行会带 HTTP 状态行（`HTTP/1.1 200 OK` / `401` / `ERR …`），把那行原文发出来最快。

## 覆盖安装失败

签名不一致。三个 CarRemote 包的证书必须是同一个（SHA-256 `0d0b4563…`），车机助手是 `Navitool Mod`（`2125e975…`）。

```bash
. scripts/config.example.sh
java -jar "$BUILD_TOOLS/lib/apksigner.jar" verify --print-certs dist/xxx.apk
```

签名库只允许移动，不允许重新生成。真要换，车机上必须先卸载（桌面图标和授权都会没）。

## 18766 打不开

1. **刚装完没打开过**：安卓对 stopped 状态的应用不投递开机广播。点一下桌面助手图标，或重启车机
2. **桌面助手没在跑**：Helper 实例在它的 Activity 里，Activity 不出现就拿不到。`/diag` 的「界面 / 引擎」两行会写明
3. **端口被占**：`adb shell "su -c 'netstat -tlnp | grep 18766'"`

## 点按钮没反应

1. 设置 →「操作记录」：每次点按钮的结果、耗时、错误都在里面，最新的在最上面
2. 设置 →「动作表」：方法不存在会标「已隐藏」——说明这台车的车机助手没有这个方法，不是网络问题
3. 「车况」里那一项的值有没有变；变了会绿一下

## 手机连不上车机

- 手机和车机要在同一个热点/局域网
- 安卓按 18766 → 18765 → 18764 并行探测；**iOS 只探 18766 / 18765**，
  所以「只有桥接包在跑」时 iOS 连不上，用安卓或浏览器
- 18766 通了页面里三个 tab 就都通（音乐和记录仪由网关转发），不用在 App 里配端口
- 地址栏手动填 `http://<IP>:18766/` 这种整串也认

## 音乐切了音源之后页面还连着旧的

18764 与 18765 互斥。外壳每 15 秒问一次 `/gateway`，后端端口变了会自动重贴音乐页。
没变就点一下「音乐控制」tab 重新贴。

## 已知问题

- **新装的车机助手要先手动打开一次**，之后才由服务接管（安卓 stopped 状态不投递开机广播）。
- **装新包必须 `am force-stop com.navi.tool` 再启动**，`Page` 有进程内缓存。
- **18.62 脱壳 dex 只有一份**。18.62 原厂包在 `apk\navitool-18.62-original.apk`（vc13），真丢了按 `docs/unpack.md` 重新脱。
- **`music\cloudmusic-car` 派生自 LGPL-3.0 项目**（`xuqian-git/cloudmusic-car`），其 `README.md` 引用的根 `NOTICE.md` 尚不存在。若将来开源，需补来源链与改动声明。
