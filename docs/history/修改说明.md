## 二、为什么要先"去壳再重打包"

原包是**百度加固**：`classes.dex` 只是壳，真正的业务代码在 `assets/baiduprotect*.i.dex` 里，由
`com.sagittarius.v6.StubApplication` 解密后动态加载。直接改壳 dex 没有意义，所以处理顺序是：

1. `apktool d` 解出资源 / 清单 / 壳 smali / assets / lib；
2. **丢弃**壳 smali、`assets/baiduprotect*`、`lib/arm64-v8a/libbaiduprotect.so`；
3. 用脱壳得到的 3 个真 dex 反汇编成 `smali` / `smali_classes2` / `smali_classes3`；
4. 清单 `android:name` 由 `com.sagittarius.v6.StubApplication` → `com.navi.tool.NaviApplication`；
5. 打补丁 → `apktool b` → `zipalign` → `apksigner`。

## 三、四项需求的落地位置

### 1) 机型 / VIN 验证 → 固定为瑞虎9

原逻辑（`MainActivity.onCreate`）：调用 `NativeBridge.getSystemVin()`，原生读系统属性
`persist.sys.navi.vin` / `persist.sys.tbox.vin`；**取不到就弹"车机助手不支持当前车机 (无VIN)"，5 秒后杀进程**。
VIN 同时被当作授权 UID（`license_uid`）参与后续授权判定。

| 位置 | 改法 |
| --- | --- |
| `NativeBridge.getSystemVin()` | native → 普通方法，直接 `return "LVVDB21B2ND000001"`（17 位，奇瑞 WMI `LVV` 段，代表瑞虎9） |

改完后任何车机都通过 VIN 门槛，且 UID 恒定，不再出现"机型不支持"退出。

> 说明：全量检索过 `com/navi` 全部业务代码与 `libnavitool.so` 字符串，**没有独立的车型白名单表**
> （不存在 `Build.MODEL` / `ro.product.model` 之类的判断）。机型门槛只有两处：本地"有无 VIN"，
> 以及服务端按 VIN 绑定车型后回 `block`。两处都已失效（见下）。

### 2) VIN 验证（Vim）→ 不再联网比对

| 位置 | 改法 | 效果 |
| --- | --- | --- |
| `MainActivity.lambda$onCreate$9` | 整段 `return-void` | 原本：联网 `fetchLicenseStatus` → `LicenseVerifier.verify` → 服务端校验 VIN/UID → `block` 则 `killProcess` + 云端配置同步。现在整条链不执行 |
| `NativeBridge.fetchLicenseStatus` | `return null` | 不再发请求 |
| `SharedPreferencesUtils.isLicenseUploaded` | 恒 `true` | 启动时不再起"上传 VIN/UID 到服务器"的线程 |
| `NativeBridge.uidSyncOnce` / `uploadLicense` | 恒 `true` | 静默成功，不发请求 |

### 3) VIP 验证 → 恒为全功能版

| 位置 | 改法 |
| --- | --- |
| `SharedPreferencesUtils.getLicenseStatus` | 直接 `return true` |
| `NativeBridge.checkLicenseToken` | `return "OK|1|0|2099-12-31"`（full=1 / block=0 / 到期 2099） |
| `MainActivity.onCreate` 标题栏 | 到期时间实参改为 `"2099-12-31"`，UI 命中 `contains("2099")` 分支显示 **"永久"** |
| `MainActivity.handleStartTrial` | `return-void`（已是全功能，试用入口短路） |
| `NativeBridge.requestTrial` | 返回 `ERR|offline_mode` |

标题栏效果：`车机助手 全功能版 版本：18.49-mod VIP到期时间：永久`，抽屉里被 `licenseStatus` 锁住的高级菜单全部放开。

### 4) 去除联网（授权链）

| 位置 | 改法 | 效果 |
| --- | --- | --- |
| `NativeBridge.requireInternet` | `false` | 不再要求联网 |
| `NativeBridge.requireVerify` | `false` | 跳过启动校验门 |
| `MainActivity.initAccessGate` | `return-void` | 不弹 OTP / 不检查网络 |
| `MainActivity.showNetworkToastOnce` | `return-void` | 不再弹"网络异常"打断使用 |
| `NativeBridge.checkAppUpdate` | 空实现 | 不查更新 |
| `NativeBridge.downloadPrefsData` | `return null` | 不下载云端配置 |
| `NativeBridge.verifySignature` | 恒 `true` | **必须**：重签名后原生签名校验会失败并 `System.exit(0)` |
| `NativeBridge.verifyTotp` | 恒 `true` | 双保险，任何 OTP 弹窗路径直接通过 |

合计 **20 处** 定点补丁，脚本可复现：`patch_smali.py`。

## 五、注意事项

1. **签名已变更**：与原版证书不同，不能覆盖安装，需先卸载旧版（本地数据/配置会清空）。
   若车机系统对包签名有白名单/系统签名要求，需要用对应平台签名重签（脚本里换 keystore 即可）。
2. **VIN 被固定**：所有设备显示同一 VIN、授权 UID 相同。因为已断授权网，不会串号；
   但如果将来开启云端配置同步，多台车会互相覆盖配置。
3. **"去除联网"的范围**：授权/校验/配置同步/试用/更新这条链全部离线；App 内本身需要外网的业务
   （QQ音乐/网易云歌词、天气预警、123网盘、下载更新等）仍会走网络，只是**不再影响启动和授权**。
4. 当前环境无 adb 设备，**未做真机安装验证**，只做了静态验证（签名/清单/对齐/dex 复核）。
5. 重打包后 `libbaiduprotect.so` 已删除，壳不会再介入；若日后要改业务逻辑，直接改
   `com/navi/tool/**` 下的 smali 再 `apktool b` 即可，不用再脱壳。

## 六、后续改功能怎么做

```bash
# 1. 重新反汇编（真 dex → smali）
java -cp "classes;apktool.jar" DexKit dis classes.dex  apk_decoded/smali
java -cp "classes;apktool.jar" DexKit dis classes2.dex apk_decoded/smali_classes2
java -cp "classes;apktool.jar" DexKit dis classes3.dex apk_decoded/smali_classes3

# 2. 改 smali（或往 patch_smali.py 里加一条 replace_method）

# 3. 打包 + 签名
java -jar apktool.jar b apk_decoded -o unsigned.apk
zipalign -f -p 4 unsigned.apk aligned.apk
java -jar apksigner.jar sign --ks debug.keystore --ks-pass pass:android \
     --ks-key-alias debugkey --key-pass pass:android --min-sdk-version 26 \
     --out 车机助手_V18.49_mod.apk aligned.apk
```
