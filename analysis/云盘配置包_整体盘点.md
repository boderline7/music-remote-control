1. **体积严重不均**：15 包共 118MB，其中两个壁纸包（静态 61MB + 视频 55MB）占 **116MB（98%）**；剩下 13 个"真配置"加起来仅 **3.38MB**。所以"整体塞进 apk"不划算，"只塞配置"很轻松。

## 三、app 怎么消费这些包（落地机制）

- 商店页（`StoreDownloadManager`）把 zip 下到 `navitool/filemanager/`，再 `ZipHelper.unzip` 解压到 `/sdcard/`（zip 内自带 `navitool/...` 前缀）。
- 功能侧直接读固定目录，**不看来源**：
  - `LogAppProfileStorage` / `LogMediaProfileStorage` / `LogAssistantProfileStorage` → `navitool/profile/{app,media,tool}/`（xml）
  - `SceneRuleStorage` → `navitool/scenefile/`（json）
  - `CarSoundManager` / `CarLinkFragment` → `navitool/mp3/`（mp3，缺失会 Toast "文件缺失"）
  - `DesktopAssistantFragment` → `navitool/wallpaper`、`wallpaper_video`、`icon`、`carlogo`
- `StoreServicePrefs` 里的 `downloaded_<包名>` 只控制商店页"已下载"标记，**不影响功能读取**。所以预置文件不需要伪造这个标记。

**关键坑**：zip 内中文文件名是 **GBK 编码**（未带 UTF-8 flag）。用 Python `zipfile.extractall` 默认按 cp437 解码会变乱码（如 `关闭音乐.xml` → `┤≥┐¬╥⌠└╓.xml`）。`fixed/` 目录已用 `cp437→gbk` 正确解码。做预置包时务必走同样的解码，否则中文规则文件名全废。

## 四、"代替云端下发"的三种做法

| 做法 | 操作 | 优点 | 缺点 |
|---|---|---|---|
| A. 独立预置 zip（推荐先试） | 把 `fixed/` 内容打包，车机上解压到 `/sdcard/` | 不动 apk、随时可替换、方便验证 | 需手动解压一次 |
| B. apk 内嵌 assets + 首启释放 | 打包进 apk，首次启动复制到 `/sdcard/navitool/` | 装完即用、无感 | 要改 smali 加释放逻辑；包体增大（核心 3.4MB 可接受） |
| C. 装完 adb push | `adb push` 到车机对应目录 | 验证最快 | 不适合下发他人 |

对**瑞虎9**的最小可用集（约 1.2MB，其余可不要）：
`HU90325`（联动 363KB）+ `0421Scenefile`（情景 5KB）+ `0317carlink`（提示音 400KB）+ `MHX0604`（免唤醒 3KB）+ `YYSS0730`（语音搜 2KB）+ `YGGestures0328`（手势 4KB）+ `ios_icon`（图标 365KB）。壁纸按喜好单独放（61MB/55MB）。

## 五、边界（哪些救不了）

- **在线音乐引擎**（酷狗/酷我/网易播放）：依赖 so 的 native 方法，V19 去 so 版已桩化成空实现。预置配置文件也救不了播放——配置文件只是"日志联动规则"，不是音源。
- **天气**：`navitool/.qw` 缓存目录 + 和风接口（so 返回的地址已桩成空），预置配置无效。
- **自动同步的那套配置**（`downloadPrefsData` → `navi_tool_prefs`）：是 so 内部的加密数据，不是这些 zip；桩成 null 后 app 用出厂默认，本就能跑，无需替代。
