## 一、18766 是什么，为什么必须注入车机助手进程

车机助手 `com.navi.tool` 原本没有 HTTP 口。改版工程做的 19 处补丁是"修改它的方法"（去 VIN/授权/联网/自校验），**不改它的进程结构**；18766 是另一条线：**把一段自写的 dex 注入进它的 APK，在它自己的进程里挂一个 `ServerSocket(18766)`**，把它的数据和按钮方法暴露成 HTTP。

- **车机助手的代码一个字节都不改。** 全部通过反射 + ContentProvider 启动钩子挂上去。
- 为什么 18766 只能在车机助手进程里：`carControlHelper` 是桌面助手 `DesktopAssistantActivity` 里的对象，跨进程拿不到。桥接包再装一份也抓不到这个实例，只会在自己进程里空转。这就是"注入 dex"这套做法存在的原因。
- 18766 同时兼做**统一入口网关**：把音乐（18765/18764）和记录仪（18767）的请求转给另外两个 App，手机和浏览器只连这一个地址。

一句话定位：**19 处补丁 = 让原厂 App 能用；18766 注入 = 在它进程里长出一套可被手机控制的 HTTP 服务 + 网关。两者是同一台车上互相独立、互不冲突的两条改动线。**

## 二、注入了什么

| 注入项 | 落地位置 | 作用 |
|---|---|---|
| `BridgeProvider`（ContentProvider） | AndroidManifest | 进程一起来系统就调 `onCreate`，最先挂上服务 |
| `BridgeService`（前台服务） | AndroidManifest | `START_STICKY`，进程被回收自己回来；常驻通知让系统不轻易动它 |
| `BridgeBoot`（开机广播 receiver） | AndroidManifest | `BOOT_COMPLETED` / `QUICKBOOT_POWERON` |
| `carbridge.html` | `assets/` | 车控页，18766 根路径直接返回 |
| `classes3.dex` | APK 根 | bridge Java 经 javac + d8 编译出的 dex，追加到原 dex 之后 |

`Bridge.install()` 拿到桌面助手 Activity 里的 `carControlHelper` 反射实例，所有车控动作都调它自己的方法——**不新建 Helper**（会扰乱界面结构，绝对不做）。

15 个 Java（在 `06_注入\bridge\`，包名 `com.navitool.bridge`）：

| 文件 | 大致职责 |
|---|---|
| `Gateway.java` | 统一入口网关，纯 TCP 字节透传（详见第四节） |
| `Bridge.java` | 核心：安装/绑定 Helper、总路由、日志 `note()` |
| `HttpServer.java` | 18766 的 HTTP 服务与请求分发 |
| `Page.java` | 页面/静态资源路由（车控页等） |
| `BridgeProvider/BridgeService/BridgeBoot.java` | 常驻三件套 |
| `Actions.java` / `Acts.java` | 动作表与动作执行 |
| `Cards.java` | 卡片数据 + 样式参数 |
| `Diag.java` / `Probe.java` | 诊断文本、能力探测 |
| `OpLog.java` | 操作记录 |
| `Json.java` / `Txt.java` | JSON 与文本工具 |

## 四、网关路由规则（`Gateway.java`）

纯 JDK `ServerSocket` 做的 TCP 反代，**只透传字节，不解析协议**——音乐端和桥接包都是单端口服务，普通 GET 返回页面、`Upgrade: websocket` 走协议 v1，网关不必理解 HTTP/WS 帧。

| 条件 | 去向 |
|---|---|
| 带 `Upgrade: websocket` | 音乐后端（车控是纯 HTTP，根路径的 WS 一定是音乐） |
| `/music` 或 `/music/*` | 音乐后端，转发前去掉 `/music` 前缀 |
| `/api` 或 `/api/*` | 音乐后端，路径原样（日志、音源切换、重启服务都在这） |
| `/dvr` 或 `/dvr/*` | 18767，路径原样（只在用户打开记录仪页时才走，网关不做后台探测） |
| 其余 | 留本地，走车控路由 |

音乐后端用 TCP 探活选定，**18765 优先、18764 兜底**，结果缓存 3 秒；连不上就清缓存下次重探。`/gateway` 返回 `{"ok":1,"music":<端口>}`（`music=0` 表示没在跑）。

> 坑：网关**故意不探 18767**。一旦顺手探一下，用户点过"断开"后记录仪又会被后台连上。

## 六、外壳与手机端

- 三个入口下发**同一份外壳**（`web/shell/` 由 `web/stitch.py` 拼进页面）。页面参数：`pane=car|music|dvr`、`embed=1`、`client=android|ios`、`cv=`、`b=`（构建号，去缓存）。
- **真机踩过的坑（重要）**：从 18766 进音乐页时走 `/music/` 反代能取到页面，但 **WebSocket 被网关接管后"握手成功→立刻断开→两秒重连"，表现就是一直"与车机断开连接"**。已改为音乐 iframe **直连 18765/18764 自己的端口**（`_shell.js` 的 `paneUrl()`），WS 不经任何中转。记录仪仍走 `/dvr?pane=dvr`。
- 温度控件：`tempBuild()` 建完立即 `tempShow()`，避免 `/temp` 返回 `v=-1` 时一直显示 `—`。车控的忙态改为"最后一次赢"队列，长按温度/风量连发。
- 手机端只是壳：安卓按 18766→18765→18764 顺序探测，iOS 只探 18766/18765（命中即停）。页面在手机 WebView 里跑，**手机端 App 不用为 UI 改动换包，刷新页面即可**。

## 七、在改版工程里出这个包

`make.py` 已把注入并进一条命令，不用再跑两个工程：

```bash
cd 车机助手                                         # 工程根目录
python make.py inspect <dex目录>                    # 先诊断脱壳 dex 能不能直接用
python make.py build --dex <dex目录>                # 纯 mod 包（去校验/联网，不带网关）
python make.py build --dex <dex目录> --inject       # 带 18766 网关的完整包 = 车上装的那个
python make.py verify <apk>                         # 校验
python make.py sync-inject                          # 从外部桥接工程刷新注入源码快照（合并后一般不用）
```

- `--inject` 内部：javac/d8 编译 bridge → manifest 加 3 个组件 → 塞 `carbridge.html` → 追加 `classes3.dex`。
- **注入源码就地读**：合并工程后，`src/bridge/src` + `web/pages/car.html` 就是唯一真相，不再依赖外部桥接工程目录。环境变量 `BRIDGE_ROOT` 可临时指向别处做对照。
- 两个固定坑：① 构建目录强制 `C:/Temp/mod_build`（`ASCII_BUILD` 可改），中文路径下 apktool 编 res 必失败；② `--inject` 默认版本 `25 / 18.73-mod`，与车上现有包一致，可覆盖安装也能退回。
- 回归基准：18.62 脱壳 dex 跑 `build --inject`，产物与 `dist\车机助手_V18.73_bridge.apk` 逐条目一致（1810 条目同名同大小，md5 因 ZIP 时间戳不同属正常）。

## 九、宿主升级保险

桥接是"接在别人 App 上"，最怕原厂升级后锚点变了接不上。工程里有 `scripts/verify_host.py`（在桥接工程，改版工程可参照同一套锚点），升级前先跑一遍：

```bash
python scripts/verify_host.py                 # 校验当前装的车机助手
python scripts/verify_host.py 新原厂包.apk     # 校验新包
python scripts/verify_host.py --json
```

检查 15 个锚点（9 致命 / 6 警告）：`DesktopAssistantActivity`、`carControlHelper`、`sendSeatCommand(4参)`、`actionSendCommand(4参)`、`carControlAdapter`、`CarControlAdapter.getData()`、座椅命令号、总线通道、prefs 键等。致命项变了就是真接不上，要先修补丁表再出包。

## 十、真机注意事项

1. **装完车机助手必须先 `am force-stop com.navi.tool` 再启动**——`RemoteWeb.page()` 有进程内缓存，不彻底杀进程会看到旧页面。
2. 新装的车机助手要先**手动打开一次**：安卓对刚装未启动的 App 处于 stopped 状态，开机广播不投递，点一次图标后服务才接管。
3. 常驻通知"车控桥接 · 18766 常驻中"（最低优先级、无声）是常驻的关键，不要关。
4. 手机上验不了车机数据：`getCarInfoValue` 返回空是正常的（测试机没有车机总线）。
5. 浏览器/WebView 里"复制导出日志"可用，手机 App 里复制不可用——尚未闭环。
