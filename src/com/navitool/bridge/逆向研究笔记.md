## 一、已经搞清楚、并已落地的（可信结论）

### 抓车控引擎的锚点
- Activity：`com.navi.tool.ui.extra.DesktopAssistantActivity`（`Bridge.java:35`）
- 持有引擎的字段：`carControlHelper`（`Bridge.java:37`）——**只读引用，绝不新建**第二个 Helper，会扰乱界面结构。
- 备用反射类名：`com.navi.tool.ui.extra.DesktopAssistantCarControlHelper`（`Acts.java:557`）
- 卡片数据链：`helper.carControlAdapter` → `getData()` / `updateCarControlCards()`（`Cards.java:33,44,74`）
- 卡片样式：adapter 字段 `cardAlphaPercent / contentFontSize / propertyTextColor / valueTextColor`；
  圆角等开关在 prefs `com.navi.tool_preferences` 里：`desktop_round_corner_enabled / car_control_card_corner_radius / desktop_card_margin`（`Cards.java:196-210`）

### 座椅（最曲折的一块，结论已定）
- **命令号**：加热 FL=`0x5F` FR=`0x60` RL=`0x8B` RR=`0x8D`；通风 FL=`0x5D` FR=`0x5E`（**只有前排**）。来自原厂 `handleSeatClick` 的 switch（`smali:5015-5031`）。
- **data = 目标档位 + 1**：关→1、1 档→2、2 档→3、3 档→4（`Acts.java:389-417`）。这条是 key，见第二节的弯路。
- 下发方法：`sendSeatCommand(int cmd, int data, boolean left, boolean heat)`（`smali:10264`，调用点 `5054`）。
  原厂 `handleSeatClick` 是「在当前档位上循环到下一档」再 +1 下发（`smali:4888-4913`）：
  当前关→data 4、3→3、2→2、1→1。所以**data 的语义就是目标档位 + 1**（关 1 / 1档 2 / 2档 3 / 3档 4），
  我们直接按目标档位下发是等价的，不需要真的去点循环。
- **两个 prefs 开关会改下发通道**（`handleSeatClick`/`sendSeatCommand` 开头读）：
  `desktop_seat_compat_mode` 开→原厂走 VR 语音 `sendVrCommandWithOperation`，不发总线命令；
  `lion_sync_service_enabled` 开→`sendSeatCommand` 走 `LionCarInfoService` SYNC（事件 0x897 加热 / 0x898 通风，bundle `status`=左右、`data`=档位值），
  关→走 `VDEvent` 0x50001（`CMD_ID`=命令号、`VALUE`=[data]）。
  **实车若出现「下发没反应」，先查这两个开关的当前值**，不是命令号错了（`smali:4749-4773,10267-10377`）。
- 状态键：`seat_heat_fl/fr/rl/rr`、`seat_vent_fl/fr`，走 `getCarInfoValue(String)` 读。
  **后排通风这台车既无命令号也无状态键**，所以前端不画那一行、后端返回 -1（`Acts.java:304-323`）。
- 前端最终只保留「关 / 3 档」两态（`web/car.html` 的 `[0, 3].forEach`）。

### 风量
- 前排 `CMD_FAN_FRONT=0x0C`（1-7 档）；后排 `CMD_FAN_REAR=0x44`、`CMD_FAN_REAR_OFF=0x43`（0-4，0 是关）（`Acts.java:136-175`）。
- 走独立 `/fan`，因为原厂界面是滑条不是按钮，方法名筛不出来，只能照抄命令号和档位范围。

### 温度
- 通道 `VD_HVAC=0x5000A`，调用 `actionSendCommand(context, 0x5000A, 0x0A, 摄氏度-15)`，15-30 ℃ 整度（`Acts.java:222-246`）。
- **坑**：`0x5000A` 是空调通道，不是座椅那组 `0x50001`。发错通道车机一声不响、不报错。`smali:8925/10237` 可复核。

### 动作表
- `/act` 参数就是**方法名本身**：`handleHvacAutoClick`、`actionSetDriveModeSport` 等，不再经过 id→驼峰→猜方法名那一层（`Acts.java:30-41`）。
- 命名规律：`handleXxxClick`（实例、0 参）/ `actionXxx(Context)` / `actionXxx(Context,boolean)`（`Actions.java:14-15,56-71`）。

### 三端口的真相
| 端口 | 谁提供 | 关键点 |
|---|---|---|
| 18766 | 车机助手（本工程 dex） | 常驻：ContentProvider + 前台服务 START_STICKY + 开机广播三重保活；车控只走它 |
| 18764 | 桥接包（官方网易云在跑） | — |
| 18765 | 第三方网易云车机版 `com.cloudmusic.car` | **也是我们自己的工程**（`work/cloudmusic-car`），不是黑盒 |

18764 / 18765 同一时刻只有一个在跑（音源只有一个）。手机端不用管端口，全探；默认进音乐页。

### 音乐页「一连上就断开」的根因
不是网络问题。删顶栏后 JS 仍引用已不存在的 `el.status / el.dot / el.refresh / el.gear`，
`connect()` 首行抛错 → WebSocket 根本没创建 → 一直显示断开。
修复：全部加空值保护（`web/remote.html:741-742,1230,1419` 等）。

## 二、研究过、走过弯路的（别再踩）

- **座椅档位固定偏移**：最早猜 `data = 档位 + N`，试 +1/+2 都错（点 3 落到 2、关不掉）。
  中间还做过「下发→回读→不匹配就换候选值→记住偏移」的闭环，仍不稳。
  最后回到原厂 smali 才拿到确定答案 `data = 档位 + 1`，一次下发到位。**以后改座椅先看 smali，别再猜。**
- **后排通风**：曾试图用语音服务兜底（`seatVentByVr` / `VR_PKG`），用户明确不要，代码已整体删除，别恢复。
- **「1 档」按钮**：用户明确只要「关 / 3 档」，不要再加中间档。
- **音乐页**：删除过重复的 `el.prev` 监听；暂停态按下一首要靠 `skipTo()` 里补 `command('play')`（`web/remote.html:1419-1423`）。
  随机按钮按用户要求挪到爱心旁（`.side-actions`），播控三键居中。
  桥接包 `remote_lunastub.html` 本来就没有循环模式按钮（官方页走歌单「随机播放全部」），不是漏做。
- **iPhone 15 大字**：Android WebView 的 font boosting，`_shell.css` 加 `text-size-adjust:100%` 解决。
- **装新版没生效**：车机助手 `RemoteWeb.page()` 有进程内缓存，装新 APK 必须**杀进程重启**；手机端只需刷新页面。
- **回收站**：Windows 上回收站的编程入口（`Add-Type` / COM `Shell.Application` / `trash`）全被这台机器的安全策略封了。
  别再试回收站 API。2026-11-16 用户要求全部清理，`dist/旧版/` 已删除；现在 dist 只留各系列最新版，
  中间版不再保留（源码在、git 有记录，需要时重新构建）。
- **iOS 云构建下载**：urllib 跟随 302 会把 token 带去 Azure blob 导致 401，要用 **curl**（跟随重定向会丢 Authorization 头）；
  Git Bash 的 `/tmp` 与 Windows Python 看到的路径不同，统一用工程内的 Windows 绝对路径。

## 三、设计约束（动代码前先读）

1. **原厂代码一个字节不改**：全部通过反射 + ContentProvider 启动钩子挂上去；原工程目录只读，只引用副本。
2. **原厂界面没有的按钮，一律不写**：写了大概率也用不了。典型是被删掉的语音兜底（`seatVentByVr` / `VR_PKG`）、
   后排通风（原厂无命令号无状态位）、驾驶模式/辅助/儿童锁整组、吹风模式/方向盘加热/大灯高度。
   加新按钮前先在原车机界面确认它真实存在，再在 smali 找到对应 `handle*` / `action*`，两者缺一不可。
3. **反射失败不抛出**：任何反射点失败都记进 log、经 `/probe` 暴露（`Bridge.java:23`）。
4. **只读引用，不新建 Helper**；依赖桌面助手 Activity 出现过（Activity 不在就绑不上，`/diag` 的「界面/引擎」两行会说明）。
5. **弹窗类操作**（吹风模式、座椅按摩、香氛）走独立窗口，数据能读，点击要看 `handle*` 是否覆盖。
6. **手机无法验证车机数据**：测试机无车机总线，`getCarInfoValue` 返回空是正常的，不是 bug。
